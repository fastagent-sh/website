# FastAgent website

This repository owns the public landing page, rendered documentation, blog, and brand assets for fastagent.sh.

- Two shells, one site. `/docs/*` runs on [Nimbus](https://nimbus-docs.com) (Astro + Tailwind), whose starter files — `src/layouts/{BaseLayout,DocsLayout}.astro`, `src/components/{Header,AgentDirective}.astro`, `src/components/ui/**`, `src/pages/[...slug]*`, `src/pages/llms*.txt.ts`, `src/styles/{globals,prose}.css` — are ours to edit, not a vendored theme. Everything else (landing, blog, 404 copy) is hand-written Astro in `src/layouts/Site.astro` + `src/styles/site.css`. `nimbus.json` records which starter files came from where; `npx nimbus-docs outdated` / `diff` compare against upstream, and neither ever rewrites a file you changed.
- The docs are agent-facing by contract, not by plugin: every page ships `/docs/<slug>/index.md`, JSON-LD in the head, and a "View as Markdown" action, indexed by `/llms.txt`, `/docs/llms.txt`, `/blog/llms.txt`, and `/llms-full.txt`. `/start.md` and `/.well-known/agent-skills/` come from the sync script instead, and `src/pages/llms.txt.ts` links them by hand. Breaking any of those is a regression, not a redesign. The starter's `.mdx` twin route is deliberately not installed: the `.md` twin *is* the source here, and it credits the upstream file as `Source:`.
- That corpus is every published page, in URL order — including `docs/design/**`, the maintainer notes, which the previous setup excluded from the agent surfaces and demoted in the index. They are public, accurate pages about the same product, and keeping them in costs one honest sentence here where filtering them out would cost a hand-rolled copy of the framework's corpus assembly. The reading order for humans is the sidebar and the `/docs/` landing page; the corpus does not restate it.
- Framework behavior and onboarding source live in `vendor/fastagent/docs/`, pinned from `fastagent-sh/fastagent`.
- Never edit `src/content/docs/docs/`, `src/generated/`, or `public/start.md`; `npm run sync:docs` regenerates them. Those pages stay `.md`: upstream prose is full of angle brackets and braces that MDX would parse as JSX. The cost is that `nimbus-docs lint` (which walks `.mdx`) never sees them, so `npm run check` carries the link check instead — every `/docs/` link resolves to a page, every sidebar entry exists, and no page is missing from the sidebar.
- The reading order of the docs is the `sidebar.items` list in `astro.config.mjs`, not the filesystem: the content tree mirrors upstream's flat `docs/` directory so its own relative links keep resolving. Nimbus autogenerates from the tree when that list is absent — don't switch, it would move every URL.
- The site palette lives in `src/theme.ts` (Catppuccin Mocha dark, Latte light) and both shells read it: `npm run tokens` generates `src/styles/tokens.css` — the site's `--*` roles, the panes' `--term-*`, and the docs' `--nb-*`, which `globals.css` hands to Tailwind as `@theme`. That file is generated, gitignored, and rebuilt before dev/check/build. Two things stay outside the palette on purpose: third-party brand colors live with the ecosystem list in `src/pages/index.astro` (and their light-mode fixups in `site.css`), and the OG card keeps its own poster colors in `scripts/render-og.mjs`.
- The mode reaches the tokens as `color-scheme`, which `light-dark()` resolves, so there is one declaration per role and a subtree that must stay dark only sets `color-scheme: dark`. Both shells write `data-mode` on `<html>` pre-paint from the same `ui-mode` localStorage key, so the reader's choice follows them across `/` and `/docs/`; `npm run check` asserts both halves of that wiring.
- `npm run check` also asserts the contrast floors (site roles and docs `--nb-*` alike), that every `--term-bg` pane pins `color-scheme: dark`, and that the committed rasters still paint the color they answer to — a ground-pixel check, so it catches a palette drift, not a composition change: re-run `npm run og` yourself after editing the card.
- `public/social-preview.png` is generated by `npm run og` from `scripts/render-og.mjs`, which holds the card as an SVG template. The card keeps its own colors — it is a poster seen alone in a feed, not a surface of the site — so it does not follow the palette. `public/favicon.png` has no source in the repo and bakes the page background into its tile, so a palette change means re-exporting it. The wordmarks (`logo*.png`) are transparent neutrals and follow no palette; the OG card embeds them as base64, so re-run `npm run og` if either is re-exported.
- Blog posts live in `src/content/blog/` (rendered by the custom blog pages). Their fences go through Astro's own Shiki pipeline, themed in `astro.config.mjs` and styled in `site.css`; the docs' fences go through Nimbus with the same two themes.
- Keep the site static: Astro, Nimbus, Tailwind for the docs, vanilla CSS everywhere else. Do not add a client framework, CMS, database, or SSR without a demonstrated need — Nimbus' interactive `<Diagram>` components need React, which is not installed and should stay that way until a page actually needs one.
- Node 22.18 or newer: the build scripts import `src/theme.ts` directly, which needs the type stripping Node turns on by default from that version.
- Run `npm run check && npm run build` before opening a PR.
- Maintainer-authored PRs may self-merge after required checks; external-contributor PRs are reviewed and merged by a maintainer.
