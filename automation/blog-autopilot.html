FastAgent blog autopilot

The autopilot selects the next due topic, grounds two model passes in the latest released FastAgent source, validates the result, builds the complete website, and opens an editorial pull request. Merging that pull request advances the calendar and uses the existing main-branch workflow to publish to Cloudflare.

One-time repository setup

  1. Open Settings → Secrets and variables → Actions.
  2. Add an Actions secret named BLOG_AUTOPILOT_API_KEY. Provider-specific ANTHROPIC_API_KEY and OPENAI_API_KEY are accepted too.
  3. Add BLOG_AUTOPILOT_PROVIDER as an Actions variable: anthropic, openai, or compatible.
  4. Add BLOG_AUTOPILOT_MODEL as an Actions variable using a model identifier available to that account.
  5. For an OpenAI-compatible third-party endpoint, add its full chat-completions endpoint as BLOG_AUTOPILOT_BASE_URL. Leave it unset for the native Anthropic and OpenAI endpoints.
  6. Confirm that repository workflow permissions allow GitHub Actions to create branches and pull requests.

Optional variables: BLOG_AUTOPILOT_REVIEW_MODEL selects a separate fact-check model; BLOG_AUTOPILOT_MAX_TOKENS sets an output ceiling from 2,000 to 32,000.

Schedule and state

.github/workflows/blog-autopilot.yml runs every Monday at 09:17 UTC. automation/blog-plan.json holds due dates, factual source files, official links, required sections, product boundaries, and status. A weekly run produces nothing until a planned topic is due.

StatusMeaning
plannedEligible after its due date.
generatedThe generated article and this state change were merged. Selection moves to the next topic.
skippedEditorially removed from the queue.

Manual operation

Use Actions → Blog autopilot → Run workflow to generate a future topic by slug. The optional date input tests due-date selection. “Skip review” is only for diagnostics; scheduled runs always use the second model pass.

node scripts/blog-autopilot.mjs select --today 2026-09-07
node scripts/blog-autopilot.mjs generate \
  --product-dir /path/to/fastagent-release \
  --topic add-ai-agent-nextjs-streaming-auth-sessions
node scripts/blog-autopilot.mjs validate \
  --file src/content/blog/add-ai-agent-nextjs-streaming-auth-sessions.md \
  --product-dir /path/to/fastagent-release

Safety boundaries

  • The configured model provider receives only selected public files from the latest npm release tag, the topic brief, and existing post summaries. Review that provider's data-retention terms before enabling the workflow.
  • External pages are linked from an approved list but are not fetched into the model context.
  • A second model pass checks the draft against the same release sources.
  • Deterministic validation rejects removed APIs, unsupported guarantees, missing official links, missing sections, unknown CLI commands, placeholders, and length violations.
  • The normal site check, production build, agent-surface check, CI, and CodeQL still run.
  • Model credentials exist only in the generation step's environment; install, build, test, git, and third-party action steps do not receive them.
  • The workflow never pushes directly to main and never merges its own article.

Why a review gate remains: no model-based fact checker can prove that public technical documentation is correct. The automation removes article-by-article writing work; a maintainer remains responsible for publication.
